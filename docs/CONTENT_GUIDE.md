# Как менять материалы дела

Каждый файл в [src/content/characters/](../src/content/characters/) отвечает за одного гражданина. Для Саши это [sasha.json](../src/content/characters/sasha.json). Сохраните стабильные `id`, если просто правите текст. После правок запустите `npm run validate:content` и пройдите раунд с начала.

## Вопросы, документы и ответы

- Во вступлении изменяйте `intro.title`, `intro.notice` и `intro.subject`. В сценах поля `title`, `subtitle` и `instruction` задают название, пояснение и подсказку ведущему. Семейство механики задаёт `type`.
- Редактируйте документы в `documents`. Сцена выводит на стол только `documentIds` в указанном порядке. Не помещайте исход инцидента в доступный до раскрытия документ или изображение.
- Для проверки досье отредактируйте текст в `facts`, а в сцене — `prompt`, `factIds` и `answerId`. Ровно одна из четырёх записей имеет `isFabricated: true` и `sourceType: "fictional"`. Буквы A–D следуют порядку `factIds`.

```json
{
  "id": "sample-fake",
  "text": "Выиграла гонку бумажных самолётиков.",
  "sourceType": "fictional",
  "isFabricated": true,
  "needsReview": true,
  "approvedForShow": false,
  "notesForOrganizer": "Пример игровой подделки. Перед показом проверить, что утверждение ложное."
}
```

Замените прежний id подделки на `sample-fake` в `factIds` и `answerId`. Обновите `explanation`, `correctFeedback` и `wrongFeedback` при изменении развязки. Для реальных фактов в активной сцене нужно `approvedForShow: true` и `needsReview: false`. Игровую подделку можно репетировать до согласования, поскольку одна запись заранее объявлена выдумкой. После согласования заведите отметки об утверждении. Поля организатора на экране отсутствуют. Держите в них только краткие рабочие замечания, доступные тем, у кого есть сборка или исходники.

Для открытой истории используйте сцену `discussion`. В `prompt` запишите вопрос, в `outcome` — заголовок, текст и поля источника. Ведущий сразу может нажать «Открыть развязку» после обсуждения. `afterNoteId` опционально связывает сцену с утверждённым показанием из `evidence`. Оно появится под исходом.

`route` показывает материалы полёта с полями `from` для места прибытия, `to` для аэропорта вылета и `after` для пункта назначения. В открытой истории путь целиком и опциональное `route.image` видны после раскрытия. `shore` с полями `title`, `distance`, `bank` и `water` сначала показывает удочку и дистанцию. Рыба, движение удочки и пройденный отрезок появляются после раскрытия. `parade` с полями `title` и `location` показывает кадр городского праздника с верёвочкой. Тягач появляется после раскрытия.

Для викторины с вариантами используйте `incident`, как в учебном деле. Укажите три `options` и id реального исхода в `answerId`. Остальные варианты помечайте `sourceType: "fictional"`.

## Улики и диалоги

1. Добавьте в `evidence` запись с `id`, `title`, `text`, `icon` и полями источника. Для готового дела используйте `selfReported` или `colleague` с утверждением показа. Подходящие значки включают `compass`, `route`, `bun`, `file`.
2. Перечислите 2–3 id в `evidenceIds` сцены `witness`. Укажите два id в `answerIds`. `conclusion` читается после формирования заключения, `alternateFeedback` — при выборе другой пары.
3. Добавьте реплику в массив `dialogue`. Допустимые значения `speaker` — `citizen` и `inspector`. Поле `revealDialogue` задаёт реплики после раскрытия истории. `visitorFraming: "forehead"` опускает портрет в окне инспектора на этой сцене. Следующая сцена возвращает обычный кадр. Паспорт использует полный портрет. `visitorBackdrop: "cockpit"` включает фон рубки на нужной сцене.

```json
{
  "dialogue": [
    { "speaker": "inspector", "text": "Материалы приобщены." },
    { "speaker": "citizen", "text": "Комиссия может задавать вопросы." }
  ]
}
```

Реплики гражданина — сценарный текст. Сверьте его с рассказом человека и согласуйте формулировку, если важно сохранить точную цитату.

## Портрет и награда

- Положите разрешённый портрет в `public/assets/people/<id>/` и укажите путь `portrait` относительно `public/`. Портреты Саши и Нияза используют прозрачные PNG 96×112 и выравниваются по подоконнику. Отсутствующий или нечитаемый портрет заменяется силуэтом. Опциональное поле `windowMark` добавляет один декоративный символ на рамку окна.
- `documents[].image` добавляет изображение в открытый документ. Игра оставит текст доступным при отсутствии файла.
- В `award` редактируются название, заслуга, поздравление и вид награды. Для `motif` доступны `compass`, `star`, `laurel`, `fishing` и `truck`. `award.image` опционально подменяет встроенную медаль.

```json
{
  "award": {
    "title": "Орден хороших попутчиков",
    "citation": "За умение собирать команду в дороге.",
    "greeting": "С днём рождения!",
    "motif": "laurel",
    "image": "assets/people/example/medal.png"
  }
}
```

## Порядок сцен и новый гражданин

1. Скопируйте готовый JSON или учебный профиль `demo.json`. Замените `id`, `displayName`, `caseNumber`, содержимое вступления, проверок и церемонии. Задайте `status: "ready"`, когда дело готово, либо оставьте черновик в формате `placeholder` с `id`, `displayName` и `preparationNote`.
2. Импортируйте файл и внесите его в объект в [manifest.ts](../src/content/manifest.ts). Если он заменяет черновик с таким же id, удалите старую запись и файл черновика. Учебные дела с `status: "demo"` запускаются из панели ведущего (кнопка открывает первое подключённое демо).
3. Порядок элементов `scenes` соответствует порядку сцен. Награждение идёт сразу после последней включённой сцены. Если в деле есть `verdict`, поставьте его последним. Необязательную сцену можно скрыть через `"optional": true, "enabled": false`. Если меняете порядок, проверьте, что ранние улики не выдают развязку позднего этапа.
4. Проверьте все ссылки на документы, факты, улики и варианты ответа. Замените чужие тексты и пути к изображениям. Затем запустите валидацию и проверьте появление дела в списке.

При ошибке валидатор выводит имя файла и путь до поля. Нереальные или неподтверждённые материалы для настоящего человека лучше держать в черновике вне активных сцен.
